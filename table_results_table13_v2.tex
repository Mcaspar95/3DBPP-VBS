% each method. LOWER OBJECTIVE IS BETTER. Every figure is the mean over
% the five instances of that configuration.
%
% WFBF is split into two columns, as main_slurm.py now runs it: the same
% heuristic under the two readings of Algorithm 1 line 15.
%
%   wfbf-corner  candidate positions restricted to corner points - the
%                origin and the corners opened by placed items. Not time
%                limited; finishes in milliseconds. NOT comparable to the
%                paper's own WFBF timings.
%   wfbf-grid    the literal enumeration: every position on the
%                beta-grid (beta=1 here). This is the reading whose TIME
%                is comparable to the paper's WFBF column. Capped at
%                3600 s in main_slurm.py. WFBF-grid (the literal position enumeration of Algorithm~1) has not been run on this grid yet and is omitted rather than shown empty.
%
% Four things to keep in mind when reading this table:
%
%  1. The MILP column is degenerate. On all 75 runs Gurobi returned the
%     EMPTY packing - no item placed, no bin opened - and reported it as
%     OPTIMAL with a zero gap, so the objective is exactly the number of
%     bins m (every bin entirely wasted). Beam search finds verified
%     V2-feasible packings of objective 0.10-0.89 on the very same
%     instances, so the MILP's optimality claim cannot be correct: the
%     model, as built at these sizes, admits no non-empty packing. The
%     column is reported as measured and is a defect to investigate, not
%     a result about the model of the paper.
%
%  2. Neither WFBF column enforces the centre-of-mass or the load-bearing
%     constraints, and wfbf-corner is not V2-feasible on 64 of the 75
%     instances, so its objective is optimistic and not comparable with
%     BS.
%
%  3. wfbf-corner's reports before the corner/grid split were written
%     under solver "wfbf" with budget tag "uncapped"; they are corner
%     runs under today's naming and are deduplicated against re-runs of
%     the same instances (identical objective, seed=1 is deterministic)
%     so each configuration is still averaged over 5, not 10.

% Four things to keep in mind when reading this table:
%
%  1. V1 and V2 MILP are degenerate on all 75 runs each: Gurobi returns
%     the EMPTY packing (no item placed, no bin opened) and reports it
%     OPTIMAL with a zero gap in well under the 3600 s budget, so the
%     objective is exactly the number of bins m. This is the SAME defect
%     already documented for V2 in table_results_table13_v2.tex and
%     table_results_table11_12_v2.tex; it now reproduces identically
%     under V1, confirming the trigger is instance size (or something
%     correlated with it), not which of V1/V2's extra constraints is
%     active. BS finds verified feasible packings of far lower objective
%     on the very same instances for both submodels, so the MILP's
%     optimality claim cannot be correct; the columns are reported as
%     measured.
%
%  2. V0 MILP behaves differently: on all 75 runs it exhausts the full
%     3600 s as TIME_LIMIT (never OPTIMAL) with a reported gap of
%     essentially 100%, and returns a NON-empty packing (20-40 items
%     placed, all m bins opened). This rules out the empty-packing defect
%     for V0 at these sizes, but every one of these packings fails
%     verification --- exclusively on "disallowed rotation", 0 centre-of-
%     mass or load-bearing violations since V0 does not check those. This
%     is the same rotation-tolerance symptom already seen on TIME_LIMIT
%     (as opposed to degenerate-OPTIMAL) MILP runs in
%     table_results_table11_12_v2.tex ($n=18$--$26$), now confirmed on
%     the multi-bin grid as well; it has not been root-caused.
%
%  3. BS is feasible on all 225 runs across the three submodels (0
%     violations) and opens all m bins on every run. It hits its 900 s
%     cap on 0/75 V0 runs, 32/75 V1 runs and 40/75 V2 runs (rising with
%     the number of active constraints, as expected), never falling back
%     to its greedy fallback.
%
%  4. The times shown for the MILP columns are solve times only; building
%     the model took a further 3.6-45.2 s (V0), 3.6-42.4 s (V1) and
%     4.4-54.8 s (V2) on average per configuration, on top of the figures
%     in the table.
